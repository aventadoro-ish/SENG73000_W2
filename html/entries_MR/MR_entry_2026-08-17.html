Non-Blocking CAN Reception

I corrected a bug caused by the Supervisory Controller's blocking CAN-message read. When no CAN frame was available, the receive function prevented the main loop from continuing, so periodic tasks such as the Elevator Controller heartbeat-timeout check could not execute. As a result, the absence of heartbeat messages did not reliably trigger fault mode.

I changed the receive path to operate without indefinitely blocking the controller loop. The Supervisory Controller can now continue running its state-machine and timeout checks when the CAN receive queue is empty, while still processing frames as soon as they become available.
