ToF addition

MoP comms PCB uses I2C2 peripheral. This is how I can set Wire to use I2C2

Wire.setSDA(I2C2_SDA);
Wire.setSCL(I2C2_SCL);
Wire.begin();
Wire.setClock(100000);

The initial setup looked okay, but at frame 30 I start getting issues. The waveform looked all right when zoomed in, but voltage drops slightly over time.

Inspected I2C connector on the PCB - looks like a bad solder joint on 3.3 V pin. Combined with lack of proper JST PH2.0 connector for DF Robot's ToF module, power stability issues seem to cause the problem. Swapped I2C connection from port 3 to port 1 and the sensor started working.

ToF Mount

Designed a mounting bracket for DFRobot VL53L0X distance sensor. No technical drawings were provided, so I used calipers to measure the board. The sensor will measure distance to the counterweight caret and will be mounted at the top of the platform.

Other issues with the schematics:

  • Selected CAN TRX chip symbol was improperly imported when KiCAD has a built-in symbol and footprint
  • Selected CAN termination configuration button is out of stock on DigiKey, which is an agreed-upon default component provider. No reason to justify this selection was provided
  • SN65HVD230 CAN TRX chip is 2.45USD, whereas the suggested schematics use 1.03USD IC (MCP2542FDxMF). No justification for IC selection was provided. Replacing component with a cheaper IC which was tested before
    • Furthermore, SN65HVD230 operates from a single supply voltage, which determines its IO and CAN voltages. For 3.3 V IO necessary for ESP32, CAN voltage will be limited to 3.3 V (see section 8.5 of the IC)
  • Generic DB-9 connector was used. No part number was provided
  • Vertical USB-C connector was used after I asked to replace it with a horizontal variant
