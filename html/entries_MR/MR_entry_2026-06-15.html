Stepper motor acceleration control and limit switches

I implemented advanced stepper motor control module for EC using Chat GPT. Use of LLM was deemed acceptable since full EC code is provided for school-built elevator platforms.
Main features of the module:

  • Interrupt-driven control loop
    • TIM6 calls Stepper ISR with 10kHz frequency
    • This eliminates the need for Stepper.tick() calls inside the main loop
  • Interrupt-driven limit switches
  • Speed and acceleration limits
  • Homing sequence
  • Automatic travel range determination
  • Serial command and status interface
The module was tested using Serial interface. It functions well, but there are a few quirks that need to be resolved.
  • Only 1 limit switch is active during travel move. The other limit switch is ignored. This behavior should be changed to enter fault mode when wrong limit switch is triggered for safety purposes.
  • movemm command has a limited range of accepted values even if the desired target is within the range of motion determined during homing procedure.
These faults were deemed non-critical for now, but will be revisited in the future.

Additionally, simplified CAN protocol was implemented to test CC issuing commands to EC to move the stepper motor.
