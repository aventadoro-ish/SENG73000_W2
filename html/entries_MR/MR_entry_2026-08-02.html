General Phase 3 Preparation

I cleaned up old Git branches left over from Phase 2. I removed the following branches:

  • KiCAD/main
  • SC/database_dev
  • SC/FSM_Phase2_dev

Based on the demonstration video recorded on Friday, July 31, I prepared the following task list:

Phase 3 Task List

  • Supervisory Controller:
    • Clean up the diagnostic print statements.
    • Correct the database request-completion logging, which is currently hard-coded for the Car Controller only.
    • Ensure that Sabbath mode stops immediately when the operating state is toggled.
    • Flush scheduler requests whenever the operating mode changes.
    • Add support for virtual door-open commands.
  • Web interface:
    • Correct the web interface because it does not currently update the elevator position.
  • Elevator Controller:
    • Correct the LCD initialization sequence, which displays “Initialized” too early.
    • Release the motor coils when the Elevator Controller is disabled, allowing the Supervisory Controller to control them indirectly.

Supervisory Controller Fixes for Phase 3

I began correcting the identified Supervisory Controller issues. I moved all CAN-related database interactions into the CAN receive-processing functions.

To add virtual door-open support, I started implementing a helper door module. This module will combine incoming door-state updates from the database and CAN bus and produce a clean is_door_open state, avoiding the need to manage the related variables and transitions directly in main.

CAN-Log Database Schema Proposal

I also proposed the following revisions to Nick for the CAN-log database schema:

  • Remove fields that store duplicated information:
    • The receive/transmit direction is not well defined across the network and can be inferred from the message ID.
    • The source controller can also be inferred from the message ID.
  • Change the message-ID field from a string to a numeric type to make sorting easier.
  • Change the data field to BIGINT so that it can store CAN frames up to eight bytes long.

Progress Status

The database request-completion logging correction was completed on August 3. The remaining print-statement cleanup, Sabbath-mode stopping behaviour, scheduler flushing, and virtual-door support tasks remained in progress.
