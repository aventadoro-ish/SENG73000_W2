Summary

Integrated floor announcement functionality into the elevator supervisory controller software. The FSM was updated so that when the elevator reaches the ARRIVED state, the controller updates the database and plays the corresponding floor announcement audio file using the Linux audio playback utility.

Floor Announcement Integration

Continued development of the Lithium Firefly elevator software by connecting the existing finite state machine (FSM) logic with the audio announcement system developed previously using the MAX98357A I2S audio amplifier.

The elevator supervisory controller now announces the destination floor after reaching the ARRIVED state. This provides audible feedback to passengers and demonstrates integration between the elevator control logic and the embedded Linux audio system.

FSM State Update

The ARRIVED state in both mainFunctions.cpp and main.cpp was updated to call the new announceFloor() function after the elevator reaches its target floor.

The database update functionality was maintained using the existing conditional compilation flag. Once the floor number is stored, the audio announcement is triggered before returning the FSM to the IDLE state. 


case STATE_ARRIVED:

#ifdef DO_USE_DB
    db_setFloorNum(targetFloor);
#endif

    announceFloor(targetFloor);

    currentState = STATE_IDLE;
    break;

Audio Announcement Function

The new announceFloor() function was added to generate the appropriate audio playback command based on the current elevator floor.

The function dynamically creates the file path using the floor number and calls aplay to play the corresponding WAV file stored within the elevator audio directory. 


void announceFloor(int floor)
{
    std::string cmd =
        std::string("/usr/bin/aplay ") +
        AUDIO_PATH +
        "floor" +
        std::to_string(floor) +
        ".wav &";

    system(cmd.c_str());
}

For example, when the elevator arrives at floor 3, the controller generates the command: 


/usr/bin/aplay /path/to/audio/floor3.wav &

This allows each floor to have a dedicated announcement file while keeping the software implementation scalable for additional floors.

Header File Update

The function prototype was added to mainFunctions.h so that the announcement function can be accessed by the main FSM logic. 


void announceFloor(int floor);

Software Integration Overview

The completed software flow is now:

  • Elevator request is received through CAN communication.
  • FSM transitions through MOVING state.
  • Target floor is reached and FSM enters ARRIVED state.
  • Database floor information is updated.
  • announceFloor() selects the correct WAV file.
  • aplay outputs the floor announcement through the I2S audio hardware.
  • FSM returns to the IDLE state.

Engineering Discussion

This update successfully connected the previously tested audio hardware with the elevator control software. By keeping the announcement logic inside a separate function, the FSM remains readable while allowing the audio system to be expanded independently.

The implementation also allows future improvements such as adding direction announcements, door status messages, emergency notifications, or replacing the Linux playback command with a dedicated audio driver.

Next Steps

  • Test announcements for all available floors.
  • Verify audio playback reliability during repeated elevator cycles.
  • Integrate audio testing with the complete CAN communication system.
  • Consider adding additional elevator status announcements.
