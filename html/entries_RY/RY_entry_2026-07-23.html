Diagnostics Page Spec

Given the spec for the Elevator Diagnostics Page: read elevator_requests from the database, decode each entry into its CAN protocol information, and display the result as a searchable/paginated table, with a link to the CAN Protocol Reference page for anyone who needs the byte-level bit layouts.

Building elevator_diagnostics.php

Started the new page with a proper admin-only session check (following Nick's code), then a single query against elevator_requests: 

if (!isset($_SESSION['logged_in']) || $_SESSION['logged_in'] !== true) {
    header("Location: ../html/login.html");
    exit("Please log in.");
}

if (($_SESSION['user_role'] ?? '') !== 'admin') {
    http_response_code(403);
    exit("Access denied; admin permissions required for this page.");
}

Replaced the chained if-statements from the draft with a source_controller → CAN message lookup array, $canMessages, so each controller's CAN ID, transmitter, recipient, and bit layout live in one place instead of being spread across conditional branches: 

$canMessages = [
    "web_floor_station" => [
        "can_id"      => "0x100",
        "transmitter" => "SC",
        "recipient"   => "EC",
        "message"     => "Supervisor Floor Request",
        "bit_layout"  => "en_floor",
    ],
    // ...additional controllers
];

diagnostics.js

Wrote diagnostics.js in vanilla JS, with no jQuery or DataTables dependency, to handle table search, column sorting, and pagination entirely client-side, keeping all database access confined to PHP. Those features were added by seraching similar diagnostics pages online.

Stylesheet Review

Reviewed the existing CANprotocol.css and elevator_control.css against the new markup and confirmed the table classes already matched. Added a small diagnostics.css for the elements the existing stylesheets didn't cover: the search bar, pagination buttons, and error banner, matching the existing color tokens and shape language.

Next Steps

  • Confirm the diagnostics page against the live database once a connection is verified.
  • Cross-check the SQL schema dumps against the actual live setup.
  • Consider adding a second table for fuller request detail.
  • Look into whether CAN bus traffic is being captured anywhere for future decoding.
