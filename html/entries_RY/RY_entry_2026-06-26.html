These helper functions translate between floor numbers and CAN message data.

Finite State Machine Implementation

The Supervisor Controller was expanded into a finite state machine (FSM) that manages elevator movement and communication between the Raspberry Pi, Cab Controller, Elevator Controller, and Floor Controllers. Rather than reacting to individual CAN messages independently, the controller now maintains its operating state and transitions only when predefined conditions are satisfied.

Implemented States

  • Idle – Waits until the cab doors are closed and a floor request is available in the queue.
  • Moving – Commands the Elevator Controller to travel to the requested destination while monitoring movement progress.
  • Arrived – Confirms that the requested floor has been reached before returning to the idle state.
  • Fault – Entered whenever movement exceeds the allowable timeout or an unexpected operating condition occurs.

Queue Implementation

Implemented a circular FIFO queue allowing the Supervisor Controller to process multiple floor requests in the order they are received.

Initial Supervisor Controller Initialization

After integrating the CAN communication libraries and database functions, the Supervisor Controller was initialized by synchronizing the elevator's starting position with both the Elevator Controller and the project database. The controller begins in the STATE_IDLE state and waits for floor requests before commanding elevator movement.

int HexFromFloor(int floorVal) {

	switch(floorVal) {
		case 1:
			return(GO_TO_FLOOR1);
			break;
		case 2:
			return(GO_TO_FLOOR2);
			break;
		case 3: 
			return(GO_TO_FLOOR3);
			break;
		default:
			return(GO_TO_FLOOR1);			// Default is to reset to floor 1 on bad input
		}
}

int FloorFromHex(int Hex){
		
	switch(Hex) {
		case GO_TO_FLOOR1:
			return(1);
			break;
		case GO_TO_FLOOR2:
			return(2);
			break;
		case GO_TO_FLOOR3:
			return(3);
			break;
		default:
			return(1);							// Default is to reset to floor 1 on bad input
		}
}
