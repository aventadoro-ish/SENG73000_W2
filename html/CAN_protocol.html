CAN bus communication

Majority of our project relies on the CAN bus communication protocol, especially for the embedded controllers to send each other updates and messages regarding the elevator. Below is a detailed look at the CAN communication structure established for our elevator. It features CAN IDs, message bytes and the bits they represent, what controller sends what message with what ID, all summarized into a table for easy-viewing.

Fields Description Value
SC_EN Supervisory Controller Enable bit 0 - disabled
1 - enabled
SC_FloorReq SC Request to EC to move elevator cabin to a given floor 0 - INVALID
1, 2, 3 - go to floor X
EC_EN ELevator Controller Enable bit 0 - disabled
1 - enabled
EC_Pos EC reports current Position of the elevator cabin 0 - moving
1, 2, 3 - currently at floor X
CC_EN Car Controller Enable - informs SC if door is closed (enable) or open (disable) 0 - door is open and cabin must NOT move
1 - door is closed and cabin can move
CC_FloorReq CC Request to SC to move elevator to a certain floor 0 - no request
1, 2, 3 - go to floor X
F1_Req Floor Controller requesting the elevator cabin to floor 1 0 - INVALID
1 - request cabin to this floor
F2_Req Floor Controller requesting the elevator cabin to floor 2 0 - INVALID
1 - request cabin to this floor
F3_Req Floor Controller requesting the elevator cabin to floor 3 0 - INVALID
1 - request cabin to this floor
