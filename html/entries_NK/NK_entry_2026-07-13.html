Which, if imported, can overwrite tables with matching names. Not a deal breaker but there should be other ways to handle this.

It also features a Window compatability problem via:

This collation belongs to MySQL 8 and isn’t fully supported by XAMPP MariaDB 10.4 server.

Hashing and Testing

The next thing that was done was hashing a password. For this, we can use PHP's built-in password system. This is done by a few commands:

password_hash() converts the password into a hash PASSWORD_DEFAULT tells PHP to use the default hashing algorithm it has echo prints the hash PHP_EOL adds a new line php.exe -r executes a short php command outside of a dedicated file.

Combining this together, we get this command:

php.exe -r 'echo password_hash("TestPassword123!". PASSWORD_DEFAULT), PHP_EOL;'

It must be ran from the proper path though so the full command is actually:

/c/xampp/php/php.exe -r 'echo password_hash("TestPassword123!", PASSWORD_DEFAULT), PHP_EOL;'

This will update the "pending" to "approved" and show when it was reviewed (approved).

SET specifies what to change (or what to SET) the values to.

SET request_status = 'approved' changes it from 'pending'.

WHERE request_id = 1 is important as it specifies what entry/row should be changed. Without it, it can risk approving every request in the table as it does not have a direct ID to work with. WHERE helps MariaDB know what exactly to change.

the ar. and u. act as aliases.

FROM access_requests AS ar LEFT JOIN users AS u

This means access_requests = ar

users = u.

So, ar.first_name is actually access_requests.first_name

Additionally, u.username becomes users.username

This part,

ON ar.request_id = u.access_request_id

Allows MariaDB to look for matching values between the tables. Remember, access_requests has:

 request_id INT UNSIGNED NOT NULL AUTO_INCREMENT,

While users has:

access_request_id INT UNSIGNED,

Both of these values should be the same.
