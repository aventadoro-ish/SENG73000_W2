Phase 2 planning meeting

On our first meeting for this part of the project, we met in a voice call and decided on a general plan for the week and for Phase 2 as a whole. The goal of the meeting was to break the project into smaller PCB subsystems, assign responsibility for each subsystem, and decide what needed to be finished first so the boards could be ordered on time.

The main time window discussed was Weeks 7-11, which covers the transition from planning and PCB design into ordering, assembly, testing, and integration.

Main Phase 2 features discussed

The team listed the main features and catch-up items that need attention during Phase 2. These include both website/software tasks and embedded/electrical tasks.

  • Server controls: allowing the elevator system to be controlled or monitored from the server-side interface.
  • LCD interface: continuing LCD-related work for system information, floor status, or user feedback.
  • Authentication: adding or improving login/auth features for the web interface.
  • Database: storing useful project data, user access information, logs, or system states.
  • Audio signals: adding buzzer/speaker feedback for elevator-like behavior.
  • ToF sensor: considering Time-of-Flight sensing for position or distance-related feedback.
  • Catch-up work: finishing or cleaning up items from Phase 1 before deeper Phase 2 integration.

PCB subsystem ownership

A major part of the meeting was dividing the PCB into smaller subsystems so each person could focus on specific circuits. This should make the schematic/layout work more manageable and reduce overlap between team members.

Nick's responsibilities

  • Buttons and LEDs: user interface inputs and visual indicators.
  • USB-C PD trigger: power delivery trigger circuit for requesting a useful supply voltage.
  • Audio: buzzer/speaker circuit for elevator-style sound feedback.
  • 7-segment display: display circuit for showing the elevator floor/status.

Rita's responsibilities

  • CAN connector: connector interface for the CAN bus wiring.
  • CAN circuit: CAN-related hardware needed for communication between controllers.
  • Load cell: circuit related to weight/load measurement.
  • Database work: starting database development during the week.

Matvey's responsibilities

  • MCU: main microcontroller section of the PCB.
  • Servos: servo control circuitry.
  • Accelerometer: acceleration/orientation sensing circuit.
  • Power regulation: regulator section for generating required board voltages.
  • BLDC driver: driver circuit for brushless DC motor control.

PCB timeline

The team also made a rough timeline so the PCB design could be completed, ordered, received, and assembled with enough time left for testing.

  • PCB design target: finish the design by 2026-07-05.
  • Expected PCB arrival: around 2026-07-10 to 2026-07-13.
  • Assembly window: assemble the PCBs around 2026-07-13 to 2026-07-17.

The general idea is to finish the schematic/layout early enough that there is still time to order parts, assemble the boards, debug hardware issues, and integrate the final circuits into the elevator system.

Design and ordering requirements

A few practical requirements were agreed on so that everyone is designing around the same expectations. These requirements help keep the boards easier to assemble and easier to source parts for.

  • EDA software: use KiCad 9.0.9 or newer.
  • Passive component size: use 0805 parts where possible, since they are reasonable to hand solder.
  • Supplier: use DigiKey for component sourcing where possible.
  • PCB quantity: order 10 PCB blanks.
  • Component quantity: order enough components for approximately 6 units.
